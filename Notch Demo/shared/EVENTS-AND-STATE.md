# Events and state

The Zustand store is the shared client state. Data schema version 2 persists fictional students, selected student and course, and attempts in `adaptlearn-demo` localStorage; the current role is session-only and follows the route. Older schema versions reset to the baseline because v1 attempts are not compatible. Invalid persisted shapes reset to baseline; a browser with unavailable or malformed storage starts from the initial in-memory data. Browser storage does not synchronize between browsers or devices.

`submit` accepts `AssessmentSubmission`, checks the active simulated role, selected student and course, enrollment, concept/course relation, unique known question IDs and answer options, then atomically records the attempt and updates mastery. A submission ID is an idempotency key: an identical retry returns the original attempt without changing mastery; reusing it for different content is rejected. A deliberate new attempt needs a new ID. Unanswered questions count as incorrect. Scores round to the nearest integer; `round(0.6 × prior + 0.4 × score)` is clamped to 0–100. Prerequisites under 70 generate review recommendations but do not block practice. Reset restores initial data and clears attempts.

The role and all state live on the client: this is a simulation contract, not an authentication, authorization or security boundary. Never use it for real users. Scenario presets and advanced events remain pending.
